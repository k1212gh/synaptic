## 성숙도 레벨 (L1~L5)

| 레벨 | 설명 | 기준 |
|---|---|---|
| L1 | 시작 | 환경 세팅 + 빈 앱 배포 |
| L2 | 기초 | Notion OAuth + DB 스키마 완성 |
| L3 | 핵심 | 임베딩 파이프라인 + Q&A API 동작 |
| L4 | 완성 | 그래프 UI + 전체 플로우 수동 테스트 통과 |
| L5 | 운영 | Sentry, 모니터링, 베타 테스터 3명 이상 |

현재 레벨: **L2** (Phase 0~7 구현 완료, 로컬 테스트 단계)

## 핵심 워크플로우

### 세션 시작
```
CLAUDE.md와 docs/Synaptic_구현계획.md를 읽고 현재 상태 요약해줘
```

### 작업 중
```
/phase N        ← 구현계획 Phase N 실행
/review         ← 변경 코드 3관점 리뷰
/fix-p0         ← P0 보안 이슈 자동 수정
```

### 세션 종료
```
/wrap           ← 오늘 작업 정리 + PLAYBOOK 업데이트 제안
/clear          ← 다음 세션 전 컨텍스트 초기화
```

## 서브에이전트 병렬화 패턴

### 언제 쓰나
- 결과가 서로 독립적인 분석 작업
- 3개 이상 파일을 동시에 검토해야 할 때
- 리포트 생성 (데이터 수집 → 취합 → 시각화)

### 실제 활용 예시

**코드 리뷰** (병렬 3개):
```
보안 에이전트: 인증/검증 누락 체크
성능 에이전트: N+1 쿼리, 캐싱 기회 체크
타입 에이전트: any 타입, 런타임 에러 가능성 체크
→ /review 스킬로 자동화됨
```

**현황 리포트** (병렬 3개):
```
코드 상태 에이전트: 파일 수, 엔드포인트 목록
보안 체크 에이전트: 취약점 스캔
문서 현황 에이전트: 미완성 Phase, TODO 목록
→ /report 스킬로 자동화됨
```

## 컨텍스트 관리 규칙

### 문맥 설계 원칙
AI는 확률적으로 동작 → 일관된 결과를 위해 컨텍스트를 명확히 설계한다.

1. **세션 시작 시 상태 명시**: "현재 Phase 3까지 완료, 오늘은 Phase 4 OAuth 구현"
2. **실패 시 에러 통째로 붙여넣기**: 요약하지 말고 원문 그대로
3. **Phase 단위 `/clear`**: 컨텍스트가 오염되지 않도록

### 컨텍스트 오염 신호
- 이전 Phase의 코드를 다시 만들려고 함
- 이미 만든 파일을 "없다"고 함
- 같은 지적을 2회 이상 반복

→ 이 신호가 보이면 즉시 `/clear` 후 재시작

## 스킬 관리 원칙

### 스킬로 만들 조건
- 같은 프롬프트를 2회 이상 반복 사용했을 때
- 결과 품질이 만족스러울 때
- 다음 세션에서도 동일하게 써야 할 때

### 스킬 업데이트 방법
1. 스킬을 쓰다가 개선점 발견
2. `/wrap` 실행 시 "이 스킬을 이렇게 바꾸면 좋겠다" 제안
3. 승인 후 `.claude/commands/` 파일 수정

### 현재 스킬 목록

| `/review` | `.claude/commands/review.md` | ✅ 활성 |
| `/report` | `.claude/commands/report.md` | ✅ 활성 |
| `/wrap` | `.claude/commands/wrap.md` | ✅ 활성 |

## 인간 병목 최소화 전략

### 리뷰 병목 해결
- 15개 취약점 → HTML 대시보드로 시각화 (`docs/security-report.html`)
- 색상 코딩 (빨강/주황/노랑/초록) → 우선순위 즉시 파악
- `/report` 스킬로 언제든지 최신 상태 재생성

### 의사결정 병목 해결
- AI가 3가지 옵션 + 트레이드오프 제시 → 건희가 선택만
- 확인이 필요한 작업은 "승인 대기" 상태로 멈춤
- 승인 없이 데이터 삭제/마이그레이션 절대 금지
